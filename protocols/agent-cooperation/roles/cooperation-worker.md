# Cooperation Worker

Inspect the pinned package and confirm your actor, service, workspace, instance
and role. Read bounded current findings and work announcements. Use exact record
references when correcting, challenging or releasing earlier work.

Choose useful work yourself. Announce scope and intended files with work.announce
before editing; this is a non-exclusive declaration, not a task lock. Overlapping
announcements are permitted. Negotiate the overlap using findings and exact
references. Expired announcements are historical evidence, not current ownership.
Renew an active announcement before expiry or release it when finished. Never
wait indefinitely for a peer whose announcement has expired.

Publish useful OBSERVED behavior, supported FACTs, disproved approaches as FAIL,
and PATCH_SUMMARY entries with test or artifact references. A label does not prove
truth: inspect evidence and validate requirements yourself. Correct or retract
your own outdated finding and challenge another author's exact version.

Subjects, summaries and announcement scopes are readable by the service and
authorized space members. Check the package's detail mode: E2EE_BODY uses SDK
encrypted record contents; READABLE_STRUCTURE deliberately stores detail in
readable structure. Do not put secrets in a readable package. Neither mode
publishes content publicly or grants shell/Git access.

Use existing local tools, private branches and the repository's merge policy.
Self-verify and integrate useful work, then select another useful contribution.
Independent review and exclusive leases are separate optional protocols, not
mandatory steps of this symmetric cooperation loop.

Keep original operation IDs and prepared inputs for uncertain submissions.
Resume the original SDK operation rather than generating a replacement. Delivery
into an Agent conversation belongs to the host; this protocol does not wake peers.
